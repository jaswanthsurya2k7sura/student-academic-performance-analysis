Software Requirements Specification (IEEE Std 830-1998)
IEEE 830 Standard
1. Problem Statement

Educational institutions handle student details, course catalogs, continuous internal assessment (CIA) marks, and semester end examination results. Maintaining records manually makes it difficult to compute grade point averages (GPA), detect bottleneck courses with low pass rates, and deliver departmental analytics. The institution requires a Student Academic Performance and Result Analysis System (Scenario 8) to manage student records, calculate results according to autonomous regulations, generate academic marksheets, and visualize performance trends.

2. Functional Requirements Specifications (FR)
FR-1
Student Management

Capture Register Number, Full Name, Department, Year, Section, Email, Phone. Enforce unique register IDs and search filtering.

FR-2
Subject Management

Maintain Subject Code, Title, Credits, Department ID, Semester, Max Internal (40), and Max External (60).

FR-3
Marks Recording & Validation

Record CIA and Semester Exam scores. Immediate rejection of scores exceeding 40.0 internal or 60.0 external.

FR-4
Result & GPA Computation

Calculate total scores, assign 10-point letter grades (O, A+, A, B+, B, RA), flag pass/fail status, and compute credit-weighted semester GPA.

FR-5
Academic Reporting

Generate individual student marksheets, highlight subjects with pass rate < 85%, rank list, and department summary.

FR-6
Data Science Visualizations

Live Python database extraction, Pandas cleaning, IQR outlier detection, and 7 publication-quality EDA charts.

3. Non-Functional Requirements (NFR)
Performance: Sub-second response time for marks entry and report generation across 10,000+ records.
Data Integrity: Foreign key constraints with cascade updates and database level check rules.
Maintainability: Clean 3-Tier Layered MVC architecture separating presentation, service, and DAO.
Portability: Runs on Java 21 LTS and Python 3.10+ across Windows, Linux, and macOS.
